All phases are integrated into one application; phase labels describe capability groups, not separate deliverables.

| Phase | Implemented capability | Main files |
|---|---|---|
| 6 | Preserve physical servers, VMs, allocation/migration, CPU/RAM checks, reset; add persistent state/revisions/rollback | `backend/simulation/{engine,store,routes,schemas}.py`; `frontend/src/pages/DataCenterSimulator/` |

## Preserved functionality

Original `/predict/workload`, `/predict/energy`, `/optimize`, simulator routes, input forms and model laboratory remain. The original Phase 6 tests are copied into `tests/test_phase6_regression.py`. Original import paths have compatibility wrappers. Supplied data files are retained byte-for-byte. Current holdouts and legacy offline-optimizer input CSVs are retained. Redundant analysis exports and old optimization results can be regenerated by the existing scripts; the unused duplicate energy model is removed. All original folder paths remain.

The supplied Phase 7 files and `train_memory.py` were empty. They are now implemented and routed. The original `App.tsx` page bodies were moved into their respective folders instead of discarding the existing interface.

## Explicit exclusions and validation limits

No real cloud mutation, autonomous deployment, trained reinforcement-learning policy, DVFS/GPU/carbon controller, network/storage capacity model or measured application SLA is claimed. The final prototype implements the master specification's simulation and integrated-optimization scope with disclosed proxy metrics. Base-paper superiority and broad research novelty remain unproven.

## Guided UI refinement

Each of the twelve page folders now exposes a page-level simulation guide through the shared help system. Dashboard’s ⓘ popup describes the complete workflow. Contextual help is defined in `frontend/src/components/help/{Help.tsx,helpContent.ts,Help.css}` and integrated beside inputs, actions, metrics and table columns. Custom-data feedback and request invalidation preserve the distinction between unsaved edits, saved observations, predictions and simulated allocations. See USER_GUIDANCE.md.
